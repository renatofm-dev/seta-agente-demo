# 008 — RAG (base de conhecimento)

## Objetivo
Conhecimento não-estruturado da empresa acessível ao agente, atrás do port VectorStore.

## Escopo
- `packages/rag`:
  ```ts
  interface VectorStore {
    upsert(ns: 'kb'|'skills', items: VectorItem[]): Promise<void>;
    search(ns, query: number[], k, filter?): Promise<Hit[]>;
    hybrid(ns, text: string, query: number[], k): Promise<Hit[]>; // tsvector + denso, fusão RRF
  }
  ```
  Impl pgvector: tabelas `documento` (fonte, hash, versão) e `chunk` (texto, embedding
  `vector(dim)`, tsvector gerado, metadados jsonb). Índice HNSW. Dimensão vinda do env.
  O namespace `skills` desta interface é consumido pela 009.
- Ingestão: `pnpm kb:ingest ./kb` — chunking por heading (~500 tokens, overlap curto),
  re-ingestão por hash (só o que mudou), embeddings via `AIProvider.embed`.
- Tool `buscar_conhecimento(pergunta)`: hybrid top-4, retorna trechos + fonte; o prompt-base
  instrui a citar a fonte quando usar KB.
- KB demo em `kb/` (escrever): política de entrega e prazos, trocas e devoluções,
  formas de pagamento e emissão de boleto, horários e contatos, cadastro de novos clientes.

## Critérios de aceite
- Pergunta de política ("como funciona troca?") respondida via KB com fonte, no simulador.
- Re-ingestão sem mudanças não regrava embeddings (teste por hash).
- Busca híbrida supera só-densa em pelo menos 1 caso de teste com termo exato (ex.: código
  de produto) — teste demonstrativo.
